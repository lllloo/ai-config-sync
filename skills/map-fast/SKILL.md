# map-fast

定範圍、讀專案、寫成關係 JSON，再由自帶的 `scripts/render-map.js` 用 vendor 的 elkjs 算佈局，產出可平移縮放的互動關係圖。從分析到繪圖全在本 skill 內完成，不外派 provider。

## 目標

快速產出風格統一的關係圖，幫助理解內容——畫**關係與約束**，不是檔案清單。圖是迭代起點：看過後回饋調整重畫，或點名某塊深入、屆時才做細查。不逐項查證，但不畫沒有依據的線；找不到依據的內容進省略表，不用推測補滿圖。

## 執行流程

1. **定義範圍**：無參數或要「大綱」→ 大綱頁；參數是業務功能名（如「核決」「請款」）→ 主題頁（兩者見「兩種標準產出」）；參數是路徑或技術子系統 → 聚焦該範圍的自由分析。不確定屬哪種就出選擇題：列出候選型態、各附一句預期產出，讓使用者挑，不問開放式問題。接著固定一句要回答的讀者問題（寫進 JSON 的 `question`），後續內容不得自行改換視角。
2. **快速偵察**：讀相關的 `AGENTS.md`、`CLAUDE.md`、`README.md`，把其中的分層、資料邊界與約束當骨架；再快掃 `import`、`require`、呼叫、讀寫與 `symlink` 補上實際關係。只展開必要檔案，不逐邊查證。
3. **產中介表示**：依 `references/graph-json.md` 直接寫出繪圖器 JSON（`nodes`、`edges`、`groups`、`omitted`），不先做表格再翻譯；邊的 `label` 為必填。JSON 只寫語意、不夾帶圖面決策。節點數**預設壓到 9 以內**，超出就收斂（合併同質節點、收攏葉群），收不下的寫進 `omitted`；使用者明說要「詳細／完整／faithful」時才放寬到 24，超過 24 一律先畫頂層。
4. **繪圖**：把第 3 步的 JSON 交給 `scripts/render-map.js` 產出 HTML。指令、schema 與圖面規格見 `references/renderer.md`。
5. **交付**：對照「硬約束」驗收語意保真與交付邊界，並說明圖中未包含的範圍。**不做繪後目視檢查**（不開瀏覽器截圖驗圖）——圖面品質由使用者目視回饋，收到反饋再退回第 3–4 步改 JSON 重產。

## 圖型範圍

本 skill 的繪圖器只畫**關係圖**：節點＋帶標籤的有向邊＋群組框，由 ELK 的 `layered` 演算法分層。涵蓋：

- 模組邊界圖／架構圖（大綱頁的 Context 與 Container）
- 狀態機（狀態為節點、轉移為邊）
- flowchart（判斷節點與出口為邊）

**不支援**：循序圖（固定 lifeline 佈局不是 ELK layered 的形狀）、ER 切片（欄位層級的表結構不是關係圖）。遇到這兩種**直接說本 skill 畫不了**就結束，不在本 skill 內硬湊，也**不退回其他 skill 或 provider 代畫**——要不要另找別的做法是使用者的決定。

## 兩種標準產出

**大綱頁（每專案一頁，上手用）**：Context（系統與外界，內部零細節）＋ Container（要分別開的程式；每條線是通訊邊界，標協定）。功能地圖、詞彙表與核心實體不是關係圖，改以終端表格輸出，不塞進圖。以「東西怎麼跑」為主體；查到的問題（命名與實作不符、設定懸空、檔案不一致）壓成單行提醒放在終端，不成為頁面主線。

**主題頁（每業務功能一頁，指派任務用）**：狀態機（規則地圖）為主圖；需要放大某一站的內部判斷時另產一張 flowchart。**狀態機一律讀實作繪製，不信 docblock／註解**——註解過期會讓圖說謊。該主題的循序圖與 ER 切片不畫，也不代為安排替代方案。

**不入常備的項目（拍板移除，勿主動提議）**：system landscape、依賴規則檢查、部署圖、整庫 ER 大圖。

## 多圖：一張圖一個檔

繪圖器產的是**帶側欄與平移縮放的整頁**，形態上不適合多圖同頁。需要多張圖時各跑一次繪圖器產成獨立 HTML（同一目錄、檔名可辨識），交付時一併列出各檔連結並說明每張圖回答的問題。**不同圖不重複回答同一問題。**

## 繪圖器

`scripts/render-map.js`，Node.js（>= 18）零外部相依，佈局用同目錄 `vendor/elkjs`（EPL-2.0 OR GPL-3.0-or-later，見 `vendor/elkjs/LICENSE.md`）。

- **佈局在產生階段算完**，產出的 HTML 只帶算好的座標與約 175 行行內 JS（平移、縮放、點選聚焦），不含佈局程式碼、不連任何網路資源。
- **`map-fast` 擁有範圍、證據與 JSON 內容；繪圖器擁有座標、樣式與頁面骨架。** 不手改產出的 HTML／SVG——要調圖就改 JSON 重產。真的需要改圖面規則時改繪圖器本體，不做一次性的產物修補。
- **繪圖器不可用時晚停**：第 1–3 步照跑，把 JSON 內容輸出到終端，說明繪圖器缺什麼後停止。不手寫 SVG、不畫終端字元圖、不改呼叫其他 provider。

## 硬約束（第 5 步逐條驗收）

前三條由繪圖器強制（不符會直接報錯），仍列出以便交付時複述：

- 每條箭頭標明關係（`關係` 欄必填），例如 `require`、`DI 注入`、`呼叫`、`寫入`、`symlink`。
- 不留孤立節點；沒有可畫關係的節點改放說明或表格。
- 完整 HTML 單檔、固定深色主題：`<!doctype html>`、`<html lang="zh-Hant">`、`<head>` 含 UTF-8 與 viewport，可獨立開啟；不產 light 版、不做主題切換。

以下兩條由 `map-fast` 自行把關：

- 不上傳到網路空間：不呼叫 `Artifact` 工具、不發佈到任何外部服務。產出頁本身不連任何外部資源（字型走系統字型序），離線可開。
- 邊的方向與關係必須對應實際看到的證據；只畫實際存在的關係。**不畫「不存在」的關係**——沒有線本身就代表不會這樣跑；約束、禁令與刻意不做的設計寫進 `groups[].boundary` 或 `omitted`，不佔一條邊。

## 產出成頁面

本節同樣適用於報告、圖表、分析結果等其他要寫成本地檔的產物。這是跨工具 skill，不假設 Claude Code 或 Artifact viewer 存在。

**落點**：判準是會不會進版控。一次性、看完就丟的一律寫 scratchpad，不落進專案；只有使用者明說要留進 git 的，才寫進當前專案的 `docs/architecture/`（沒有就建），並說明放在哪。不要自己判斷值得保留就寫進專案。`docs/architecture/` 內容進版控、可 commit，不加進 `.gitignore`。**收的是描述專案現況的文件**（架構圖與配套文字）；判準是內容性質而非誰產出的，人寫或 AI 產都放這裡。動工前的設計提案／RFC 不屬於此（那是計畫、不是現況），要留另開 `docs/design/`。`artifacts/` 與 `docs/ai/` 是**舊落點**：新產出一律不寫進去；專案裡既有的這兩個資料夾若存放先前產出的 AI 頁面，一律搬到 `docs/architecture/`（有版控用 `git mv` 保留歷史）並告知使用者，不必再問。CI 產物、建置輸出等專案自身用途的同名資料夾不算，不動也不搬。

**連結**：產生頁面就主動附上可點連結，不必等使用者開口要。WSL 檔案給 `file://wsl.localhost/<distro>/<絕對路徑>`（distro 取 `$WSL_DISTRO_NAME`，正斜線）。終端不對它上色是正常的，照樣點得動，不要因此改用別的做法。**檔名一律純 ASCII**（小寫英數與 `-`）：檔名含中文會讓連結打不開，說明性文字留在回覆裡、不進檔名。也不要改給 Windows 原生路徑（`C:\…`）——終端不會把它辨識成連結，根本點不動。

**短內容不必開檔**：表格、程式碼、清單直接輸出終端；單純的一對一來源／目的地對應改用表格。示意圖不在此列——不分大小一律走繪圖器。
