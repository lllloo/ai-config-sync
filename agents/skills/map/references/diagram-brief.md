# 圖面 brief 與 rendering contract

在繪圖前，為**每一頁**寫以下四項。這是內容與畫面之間唯一必要的中介層；不要建立通用 IR、座標系統或另一個 renderer。

1. **讀者問題與圖型**：一句問題，以及 architecture、dependency、sequence、data-flow、flowchart 或 state machine 之一。
2. **節點與邊**：節點名稱／角色；每條邊的方向、動作或資料標籤。`禁止` 關係也要列出，並說明證據。
3. **證據與省略**：每個關係的程式碼位置或文件來源；不夠確定、超出範圍或改用表格的項目。
4. **頁面銜接**：這頁承接哪一頁、讀者看完要理解什麼；主題跨頁時，保留同一實體名稱與輔助色。

## 組頁

以單一 HTML shell 放入多個 `.page` panel。使用原生 `<button role="tab">` 與 `aria-selected` 切換；上一頁／下一頁與左右方向鍵呼叫同一個切換函式。切換只改當前 panel，不重新生成 SVG 或載入資源。

每頁包含：頁碼、問題式標題、SVG、圖例、1–3 句解讀、證據與省略項。總覽頁先顯示；閱讀順序要與核心路徑一致。

## SVG 排版

- 以層或時間軸決定方向，再放節點；不要先排方框才硬接線。
- 節點間預留至少一個標籤寬度，連線從框邊出入；箭頭標籤不壓在節點或另一條線上。
- 架構圖把群組／邊界置於節點下方；流程圖讓時間單向流動。主路徑採最醒目的實線，次要或例外路徑採虛線並降低對比。
- 同一種類使用相同形狀；關鍵、外部與禁止關係同時有文字或圖示區別，不能只有色彩差異。
- 若長標籤無法在固定節點內換行，縮短顯示名並在旁註保留全名；不要把字縮小到 14px 以下。

## 輕量靜態檢查

交付前確認 HTML 有 doctype、語言、charset、viewport、可操作的 tabs、每頁一張有 title/desc/viewBox 的 SVG；所有節點與箭頭標籤都有文字內容。確認沒有 `<script src>`、`<link href="http`、`fetch(`、`localStorage` 或外部圖片。這是快速的結構檢查，不取代使用者對內容正確性的回饋。
