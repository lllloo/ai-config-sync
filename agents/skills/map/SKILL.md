# map

畫出這個專案的架構——**關係與約束**，不是檔案清單。

## 畫什麼

- **目錄樹不是架構**。把目錄結構換成方框等於零資訊增量，`tree` 已經做完那件事了。架構在「誰依賴誰、哪個方向不准反過來、資料怎麼流、跨過哪些邊界」裡。

- **先讀這個專案自己宣告的架構主張**——`CLAUDE.md`／`AGENTS.md`／`README.md`，有 `openspec/specs/` 就一併讀。這類檔案常直接寫著分層與禁令（「功能模組不反向 require 主入口」「X 永不被寫入或讀取」），那是圖的骨架。

- **再用程式碼驗證**。搜尋實際的 `import`／`require`／呼叫方向，確認文件說的跟程式碼一致。**不一致的地方本身就是最值得畫的東西**。宣稱驗證過什麼就只宣稱驗過的那些，未核對的主張要標明來源是文件。

- **超過 10 個框就聚焦**。先畫頂層，再說明哪幾塊可以展開讓使用者挑。`/map <路徑或子系統名>` 聚焦那一塊的內部。

- **每個箭頭都標明是什麼關係**（`require`、`DI 注入`、`寫入`、`symlink`）。沒有關係要表達的框就不要放進圖裡；孤立的方框是清單，不是架構。

- **把禁令畫出來**——「不准反向依賴」「永不觸碰」這類約束用斷開的箭頭或明確註記呈現。它們往往是這個專案最花力氣維護的部分，卻最容易在圖裡消失。

- **單純的「來源對目的地」對應用表格**，不要畫成圖——一對一關係沒有機制可看，畫成方框只是把表格變難讀。

- **講清楚你沒畫什麼**。範圍聚焦時要說明省略了哪些部分，否則讀者會把圖當成全貌。

## 產出成頁面

架構圖幾乎必然超過終端能承載的複雜度，也是會想再看的東西，所以**產出成 HTML 檔，不要只在終端畫 ASCII**。例外只有使用者明講要快速看一眼，或整張圖真的只有三五個框。

以下同樣適用於其他要寫成本地檔的產物（報告、分析結果）。

**落點**：一次性產物寫 scratchpad 目錄；要保留的寫進當前專案的 `./artifacts/`（沒有就建），並說明放哪。

**連結**：**產生頁面就主動附上可點連結，不必等使用者開口要。** WSL 檔案給 `file://wsl.localhost/<distro>/<絕對路徑>`（distro 取 `$WSL_DISTRO_NAME`，正斜線）。**終端不對它上色是正常的，照樣點得動，不要因此改用別的做法。** 唯一例外：頁面非 HTTP 來源不能運作（CORS 等）才背景起 `python3 -m http.server <port> --bind 127.0.0.1`，任務結束時關掉。純路徑與 `wslview` 只當備援。

**寫成可獨立開啟的完整 HTML**：`<!doctype html>`、`<html lang="zh-Hant">`、`<head>` 內含 `<meta charset="utf-8">` 與 viewport，reset 自己帶。只寫內容片段、指望外層平台包 `<head>` 的寫法，用瀏覽器直接開會變中文亂碼。

**設計品質**：需要校準時載入 `artifact-design` skill，內容幾乎全數適用本地檔。**兩處例外**：字型 inline 成 data URI 的結論不變（理由改為離線可開、單檔可搬）；深色模式只需 `prefers-color-scheme`，`data-theme` 是 Artifact viewer 專有，要手動切換得自己寫按鈕。

**畫圖機制**：載入 `artifact-diagramming` skill，其 HTML lane **全數適用本地檔、無例外**——手寫 inline SVG、零 runtime，不要因為不是 Artifact 就改用繪圖函式庫、CDN 或外部圖片。

**短內容不必開檔**：表格、程式碼、清單、三五個框的示意圖直接輸出在終端。
